# 결정이 필요한 항목 (Open decisions)

작업하면서 **내가 임의로 정하면 안 되는 것들**만 모아둔 문서입니다. 각 항목에 현재 상태 ·
선택지 · 내 추천을 적어 두었습니다. 답을 주시면 바로 반영합니다.
(자율 판단으로 처리한 것들은 `docs/DECISIONS.md`와 `apps/android-native/NATIVE_ROADMAP.md`에 기록)

최종 수정: 2026-07-29 · 대상: 네이티브(Kotlin/Compose) 클라이언트 + 기존 Fastify/Postgres 백엔드

## 1. 서버 주소 · 배포 — ✅ 결정됨(2026-07-29): **Supabase**

- 사용자 결정: 별도 API 서버 운영은 부담 → **Supabase Postgres + Auth + Edge Function** 으로 이전.
- 준비 완료(배포만 남음): `supabase/migrations/*`(스키마 + RLS + 가입 트리거), `supabase/seed.sql`,
  `supabase/functions/game`(기존 `GameService`·`game-core` 재사용), 앱은 `-PSUPABASE_URL/-PSUPABASE_ANON_KEY`
  만 주면 Supabase 모드로 전환. 절차: **`docs/SUPABASE_SETUP.md`**
- **내가 못 하는 것:** 프로젝트 생성·링크(사용자 계정 필요). `npx supabase login` 후 알려주시면 나머지는 제가 합니다.
- 3번(웹 유지 여부)과 9번(DB)은 이 결정에 흡수됩니다 — DB는 Supabase Postgres.

## 2. 인증 방식

- **현재:** `POST /auth/dev/login`에 핸들(닉네임)만 넘기면 토큰이 나오는 **개발용 로그인**입니다.
  비밀번호도, 검증도 없습니다. 실서비스에 그대로 쓰면 안 됩니다.
- **선택지:** (a) Google 로그인(Play 연동 자연스러움), (b) Apple/Google 둘 다(iOS 계획이 있다면),
  (c) 이메일 매직링크, (d) 당분간 개발용 유지.
- **추천:** (a) Google 로그인 하나로 시작. 어느 쪽이든 백엔드 토큰 발급 로직 교체가 필요합니다.
- **2026-07-29 Supabase 전환 반영:** 앱은 **익명 로그인**으로 시작합니다(러너 이름은 메타데이터).
  나중에 Google을 붙여도 같은 auth 사용자에 연결되어 게임 데이터가 유지됩니다. 즉 이 항목은
  "언제 Google을 붙일지"만 남았고, 지금 당장 막히는 것은 없습니다.
- **이전 임시 조치(로컬 Fastify 전용):** 원래는 `demo` 계정만 로그인돼 **신규 사용자가 아예 시작할 수 없었습니다**.
  인메모리(개발) 저장소에 한해 처음 보는 이름이면 빈 계정을 만들어 주도록 바꿨습니다.
  **Postgres 경로는 일부러 그대로 두었습니다** — 실제 가입은 위 인증 방식을 정한 뒤 그 위에 얹어야 합니다.
  앱 로그인 화면에도 러너 이름 입력란이 생겼습니다(스펙 08 온보딩에 해당).

## 3. 웹(apps/web)과 Capacitor 빌드를 유지할지

- **현재:** 웹 PWA(`apps/web`)와 Capacitor 하이브리드 APK(`apps/web/android`)가 그대로 남아 있고,
  네이티브 앱(`apps/android-native`)이 같은 기능을 다시 구현했습니다.
- **비용:** 게임 밸런스 수식이 **두 곳**(웹은 `packages/game-core`, 네이티브는 `data/Balance.kt`)에
  존재합니다. 한쪽만 고치면 미리보기 숫자가 어긋납니다.
- **선택지:** (a) 네이티브만 유지하고 웹/Capacitor는 보관용으로 동결,
  (b) 웹도 계속 관리(마케팅 페이지·리플레이 공유용), (c) 웹 삭제.
- **추천:** (b)의 축소판 — 웹은 "리플레이 공유 + 랜딩" 용도로만 남기고 앱 기능은 네이티브만 갱신.
  선택 (a)/(c)라면 아래 4번(리플레이)도 같이 결정해야 합니다.

## 4. 리플레이 공유 링크의 목적지

- **현재:** 웹에는 `/replay/<base64>` 공개 페이지가 있어 링크만으로 전투가 재생됩니다.
  네이티브에는 아직 없습니다.
- **선택지:** (a) 웹을 공개 배포하고 네이티브는 그 URL을 공유(가장 저렴, 3번과 연동),
  (b) 앱 딥링크(`hitrace://replay/...`)만 지원 — 앱 미설치자는 못 봄,
  (c) 둘 다(웹 링크 + 앱 설치 시 앱으로 열기).
- **추천:** (a) 먼저, 여유되면 (c). 결정 전까지 네이티브 공유 버튼은 보류합니다.

## 5. 결제 (시즌 프리미엄 패스 ₩5,900)

- **현재:** 시즌 화면에 가격만 표시되고 **구매 동작은 없습니다**. Google Play Billing 미연동.
- **필요 결정:** 실제 판매 여부, 상품 구성(패스만 / 스킨 개별 판매), 가격.
  Play 결제는 개발자 계정·상품 등록·서버 영수증 검증이 필요합니다.
- **추천:** 출시 1차에는 결제 제외(무료), 리텐션 확인 후 도입. "Zero pay-to-win" 원칙상
  스탯에 영향 없는 코스메틱만 판매 대상입니다.

## 6. 스토어 출시 정보

- **현재:** 패키지 ID `app.hitrace`, 앱 이름 "HitRace", 기본 런처 아이콘, 디버그 서명.
- **필요 결정:** 최종 앱 이름/한글 표기, 패키지 ID 확정(출시 후 변경 불가),
  아이콘·스토어 스크린샷, 개인정보처리방침 URL(위치 권한 사용 시 필수), 릴리즈 키스토어 보관 위치.
- **추천:** 패키지 ID는 `app.hitrace` 같은 형태로 정리 후 고정. 키스토어는 사용자가 직접 생성·보관.

## 7. 백그라운드 러닝 추적 — ✅ 결정됨(2026-07-29): 구현 완료

- 사용자 결정: **백그라운드 추적 필요**. → 포그라운드 서비스(`RunTrackingService`, `location` 타입)로
  구현했습니다. 화면을 끄거나 다른 앱을 써도 GPS가 계속 기록되고, 상단에 "러닝 기록 중 · 거리 · 시간 ·
  페이스" 알림이 실시간으로 갱신됩니다. 에뮬레이터에서 화면 OFF 상태로 검증(0.16km→0.56km 누적).
- 러닝 상태는 화면이 아니라 서비스가 들고 있어, 앱을 나갔다 들어와도 이어집니다.
  일시정지 화면에 **"이 러닝 버리기"** 를 넣어 진행 중인 기록을 명시적으로 폐기할 수 있게 했습니다.
- **출시 전 남은 관련 작업(사용자 확인 필요):**
  - Play 콘솔에 **포그라운드 서비스(location) 사용 목적** 신고가 필요합니다(위치 권한 사용 설명 + 시연 영상).
  - 배터리 최적화 예외 요청은 넣지 않았습니다(정책상 심사 부담) — 장시간 러닝에서 문제되면 재검토.
  - `ACCESS_BACKGROUND_LOCATION`은 **일부러 요청하지 않았습니다**(포그라운드 서비스만으로 충분,
    심사 난이도 급증을 피함). 앱을 완전히 종료한 뒤 자동 재개는 지원하지 않습니다.

## 8. 언어

- **현재:** 네이티브는 **한국어 전용**(문자열 하드코딩). 웹에는 ko/en 토글이 있었습니다.
- **선택지:** (a) 한국어만, (b) 영어 추가(strings.xml 추출 + 번역).
- **추천:** 국내 출시가 목표면 (a) 유지. 해외도 생각 중이면 지금 문자열을 빼두는 편이 쌉니다.

## 9. Postgres 연결 (기존 이슈, 그대로 유효)

- **현재:** API는 `DATABASE_URL`이 없으면 **인메모리**로 동작합니다. 서버를 껐다 켜면 데이터가
  초기화됩니다(지금 테스트 계정도 그렇습니다). 로컬 PostgreSQL 17은 설치돼 있으나
  비밀번호를 몰라 연결하지 못했습니다.
- **필요:** 사용자가 `DATABASE_URL`을 알려주거나, 새 DB를 만들 권한.
- **추천:** 배포 서버(1번)와 함께 관리형 Postgres를 쓰는 편이 깔끔합니다.
