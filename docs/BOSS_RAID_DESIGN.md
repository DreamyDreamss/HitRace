# 동네 보스 · 레이드 — 설계

작성 2026-08-01. 확정 결정: **2계층(동+구)** · **격파 시 즉시 다음 단계** · **러닝 × 검 CP** ·
**보스 전용 재료 신규**.

---

## 왜 이 컨텐츠인가

지금 HitRace의 루프는 **달린다 → 검이 나온다 → 강화한다 → PvP**입니다. 문제는 끝이 PvP 하나뿐이고,
PvP는 비동기 자동전투라 "왜 오늘 나가야 하는가"에 대한 답이 약합니다. 그리고 러닝 앱인데
**장소가 아무 의미가 없습니다** — 어디를 달리든 똑같습니다.

보스는 그 두 구멍을 동시에 막습니다.

- **장소에 의미를 준다.** 내가 사는 동네가 게임판이 됩니다. 같은 5km라도 우리 동네에서 뛰는 것과
  출장지에서 뛰는 것이 달라집니다.
- **오늘 나갈 이유를 준다.** 보스 HP가 62% 남아 있고 일요일에 정산된다면, 그건 마감입니다.
- **기존 시스템이 전부 쓰인다.** 러닝 → 주조 → 강화가 전부 데미지로 환산됩니다. 지금은 검을 키워도
  PvP 말고는 쓸 데가 없습니다.
- **혼자여도, 여럿이어도 성립한다.** 신규 앱의 현실(한 동에 1명)과 목표(동네가 같이 잡는다)를
  같은 설계로 커버합니다 — HP가 참가자 수에 따라 자랍니다.

핵심 루프:

```
달린다 → 동네 보스에 데미지 → 격파 → 마력석 →
  검 각성(강화 상한 돌파) → 더 센 검 → 더 큰 데미지 → 더 높은 단계 보스
```

## 1. 지역 — 2계층

| 계층 | 개수 | 데이터 | 주기 | 성격 |
|---|---|---|---|---|
| **동** (행정동) | 3,482 | `korea.geojson` (1.5MB, 코드+이름) | 격파 즉시 다음 단계, 일요일 정산 | 내 주간 의식. 혼자도 가능 |
| **구** (시군구) | 230 | `sigungu.geojson` | 월간 | 대규모. 동 러닝이 자동으로 함께 기여 |

두 데이터셋 모두 **이미 `D:\Rundex\app\src\main\assets\regions\`에 있습니다.** 외부 API 의존이
없다는 뜻이고, 이건 `docs/RUNDEX_LESSONS.md`에 적어둔 "SLA 없는 무료 서버에 기대지 말 것" 원칙과
맞습니다.

### 서버가 권위를 가진다

지역 판정은 **PostGIS로 서버에서** 합니다(클라이언트가 "나 연남동이야"라고 주장하게 두면 안 됩니다).
Supabase에 `postgis` 확장이 사용 가능한 것을 확인했습니다.

```sql
create table hitrace.regions (
  code        text primary key,          -- '1144063' (행정동) / '11440' (시군구)
  name        text not null,             -- '연남동' / '마포구'
  sido        text,                      -- '서울특별시' — 중구·동구는 여러 시도에 존재
  level       text not null,             -- 'dong' | 'gu'
  parent_code text references hitrace.regions(code),
  geom        geometry(MultiPolygon, 4326) not null,
  centroid    geometry(Point, 4326) not null
);
create index regions_geom_gix on hitrace.regions using gist (geom);
```

### 러닝 → 지역 배분

한 러닝이 여러 동을 지나갑니다. **경계에 사는 사람이 손해 보면 안 되고**, 여러 동네를 도는 러닝은
오히려 장려할 만합니다. 그래서 단일 귀속이 아니라 **거리 비례 분배**입니다.

1. 저장된 다운샘플 경로(최대 300점)의 각 점을 `ST_Contains`로 동에 매핑
2. 구간 거리를 그 구간 시작점의 동에 가산 (공백 구간 `gap`은 제외 — 이미 거리에서 빠짐)
3. 러닝 총 거리의 **10% 미만인 동은 버림**(노이즈), 상위 **3개 동**까지만
4. 각 동의 상위 구(`parent_code`)에도 같은 거리가 합산 — **한 번 달리면 동과 구 둘 다 때립니다**

```
6.2km 러닝 → 연남동 3.4km(55%) · 서교동 2.5km(40%) · 동교동 0.3km(5% → 버림)
           → 마포구 5.9km
```

### 지역이 없을 때

- 국내 경계 밖 → 보스 없음. 러닝은 정상 저장, 화면에 "이 지역은 아직 보스가 없습니다"
- 실내/트레드밀 러닝 → GPS 없음 → 데미지 없음. **의도된 것입니다.** 보스는 장소에 대한 컨텐츠입니다
- 지역 판정 실패 → 러닝 저장은 절대 막지 않습니다(실패해도 조용히 넘어감)

## 2. 보스

### 생성

지역에 **처음 러닝이 들어온 순간 지연 생성**됩니다. 3,482마리를 미리 만들어두지 않습니다.

```sql
create table hitrace.bosses (
  id           uuid primary key,
  region_code  text not null references hitrace.regions(code),
  level        text not null,              -- 'dong' | 'gu'
  cycle_key    text not null,              -- '2026-W31' | '2026-08'
  tier         int  not null default 1,
  name         text not null,              -- '연남동의 밤안개'
  seed         text not null,              -- 외형·이름 생성 시드
  max_hp       bigint not null,
  hp           bigint not null,
  participants int not null default 0,
  spawned_at   timestamptz not null default now(),
  killed_at    timestamptz,
  unique (region_code, cycle_key, tier)
);
```

### 이름과 외형

**절차적 생성.** 검이 경로에서 나오듯 보스도 데이터에서 나옵니다 — 이 앱의 정체성입니다.

- 이름: `{지역명}의 {수식어}` — 수식어는 `seed`로 고른 목록에서(밤안개, 돌무지, 옛담장, 물그림자…).
  지역명이 이미 고유하므로 중복 걱정이 없고, 한국어로 자연스럽습니다.
- 외형: `seed`에서 파생한 **Canvas 실루엣**. 이미지 에셋 0개. `BladeSpine`과 같은 접근 —
  다각형 실루엣 + 단계별 색/각/뿔 개수. 단계가 오를수록 실루엣이 커지고 각이 날카로워집니다.

### HP — 참가자가 늘수록 **1인당 부담이 줄어든다**

이게 이 설계에서 제일 중요한 숫자입니다. 신규 앱은 한 동에 1명이고, 그 1명이 못 잡으면 컨텐츠가
없는 것과 같습니다. 반대로 100명이 모였는데 5분 만에 죽으면 레이드가 아닙니다.

```
max_hp = BASE × 1.6^(tier-1) × (1 + 0.6 × (participants - 1))
```

`BASE`는 **CP 1600 검으로 6km를 5'30"에 달린 러닝 ≈ 10,000 데미지**를 기준으로,
`BASE = 40,000` (솔로 4회 러닝 = 한 주). 참가자가 늘면:

| 참가자 | HP 배수 | 1인당 부담 |
|---|---|---|
| 1명 | ×1.0 | 40,000 |
| 3명 | ×2.2 | 29,300 |
| 5명 | ×3.4 | 27,200 |
| 20명 | ×12.4 | 24,800 |

**모이면 모일수록 각자는 편해집니다.** 이건 의도적입니다 — 동네 사람을 부를 이유가 생깁니다.
새 참가자가 합류하면 HP 상한과 잔여 HP가 같은 비율로 늘어, 이미 넣은 기여가 희석되지 않습니다.

### 격파 → 즉시 다음 단계

죽으면 그 자리에서 `tier + 1` 보스가 올라옵니다. 열심히 뛰면 진도가 계속 나갑니다.

```
월  연남동 보스 1단계 격파 ✓ → 2단계 등장 (HP ×1.6)
목  2단계 격파 ✓            → 3단계 등장 (HP ×2.56)
일 24:00 KST 정산: 이번 주 최고 3단계 기록
    다음 주는 2단계부터 시작 (max(1, best-1))
```

진도가 완전히 리셋되지도, 무한히 누적되지도 않습니다. `pg_cron`으로 주간/월간 정산을 겁니다.

## 3. 데미지 공식

```
damage = round(
    distanceInRegionKm
  × paceFactor
  × elevationFactor
  × swordFactor
  × streakFactor
)
```

| 항 | 계산 | 범위 | 의도 |
|---|---|---|---|
| `distanceInRegionKm` | 그 동네 안에서 달린 거리 | — | 기본. 달린 만큼 |
| `paceFactor` | 6'00"에서 1.0, 4'00"에서 1.4 (선형, 클램프) | 0.8~1.4 | 노력 보상, 상한 有 |
| `elevationFactor` | `1 + gain/500`, 상한 1.3 | 1.0~1.3 | 언덕 |
| `swordFactor` | `(equippedCp / 1000)^0.8` | 0.5~ | **육성이 개입하는 지점** |
| `streakFactor` | `1 + 0.03 × streakDays`, 상한 1.2 | 1.0~1.2 | 기존 연속일수 재사용 |

검 미장착 시 `swordFactor = 0.5` — 기여는 되지만 약합니다.

`^0.8`(제곱근에 가까움)인 이유: CP가 3배가 되어도 데미지는 2.4배입니다. 검이 분명히 중요하지만
**고인물이 뉴비 100명을 압도하지는 못합니다.** 러닝 앱이므로 거리가 1차, 검이 배수입니다.

```
6.2km · 5'10"/km · +54m · CP 1644 · 연속 3일
  = 6.2 × 1.23 × 1.11 × 1.51 × 1.09 ≈ 13,900
같은 러닝, CP 4000 각성검
  = 6.2 × 1.23 × 1.11 × 3.03 × 1.09 ≈ 27,900
```

### 어뷰징 방지

- **검증된 러닝만** 데미지를 냅니다. 기존 `validateRun`을 그대로 씁니다 — 텔레포트·탈것·
  기준 미달 러닝은 0입니다.
- **하루 3회**까지만 데미지에 반영(지역별). 그 이상 뛰는 건 자유고 기록에는 남습니다.
- 데미지는 러닝 제출 시 서버가 계산합니다. 클라이언트는 숫자를 보낼 수 없습니다.
- 재전송(멱등)된 러닝은 두 번 때리지 않습니다 — `findRunByStart`로 이미 막혀 있습니다.

## 4. 보상 — 마력석과 각성

### 마력석 (새 재화)

보스에서만 나옵니다. `Currency`에 `manaStone` 추가.

```
내 몫 = 단계별기본 × (0.5 + 0.5 × 내기여비율)
```

기여 1% 미만은 제외. 절반은 참가만 해도 주고 절반은 기여도 비례 — **막타 친 사람이 다 가져가지
않습니다.** 마지막 일격 + 최다 기여자에게는 보너스와 **동네 명단 등재**.

### 각성 — 강화 상한 돌파

지금 강화는 `+N`이 오를수록 성공률이 떨어져 자연히 벽에 부딪힙니다. 각성은 그 위에 얹는 축입니다.

| 단계 | 비용 | 효과 |
|---|---|---|
| 각성 1 | 마력석 8 + 철광석 800 | 전 스탯 +6%, 칼날에 각성 문양 1 |
| 각성 2 | 마력석 20 + 철광석 2,000 | +13%, 문양 2 |
| 각성 3 | 마력석 45 + 철광석 4,500 | +21%, 문양 3, 이름 앞에 `眞` |
| 각성 4 | 마력석 90 + 철광석 9,000 | +30%, 칼날 광채 |
| 각성 5 | 마력석 180 + 철광석 18,000 | +40%, 명검 도감 등재 |

각성은 **실패하지 않습니다.** 강화는 도박이고 각성은 성실함입니다 — 두 축의 성격을 다르게 둡니다.

### 보스 각인

보스에서만 나오는 각인. **기존 각인 시스템을 그대로 씁니다**(새 서브시스템 0개).
`engravings` 테이블에 `source = 'boss'` 항목을 추가하면 끝입니다.

## 5. 화면

### 신규

1. **동네 보스** — 보스 실루엣 + HP 바 + 단계 + 내 데미지 + 기여 순위표 + 남은 시간
2. **구 레이드** — 같은 구조에 동별 기여 순위 추가
3. **각성** — 검 상세 안에서 마력석 소비

### 기존 화면 통합

- **홈**: 동네 보스 카드 — 이름, HP %, 내 순위, 남은 시간. 러닝 CTA 바로 위
- **요약/주조 결과**: "이 러닝으로 연남동의 밤안개에 **13,900** 데미지"
- **프로필**: 격파 수, 칭호, 최다 기여 동네
- **검 상세**: 각성 단계 표시

기존 5탭(홈·컬렉션·대전·랭킹·프로필)은 유지하고, 보스는 **홈에서 진입**합니다. 탭을 늘리면
러닝 앱이 아니라 게임 런처처럼 보입니다.

  ..._regions.sql        PostGIS + regions 테이블 + GIST 인덱스
  ..._boss.sql           bosses / boss_damage / boss_kills / run_regions
  ..._awakening.sql      swords.awakening, wallet.mana_stone
supabase/functions/game/  GET /boss, GET /boss/:id/leaderboard, POST /swords/:id/awaken
apps/android-native/.../ui/BossCanvas.kt   절차적 보스 실루엣
apps/android-native/.../ui/screens/BossScreen.kt · RaidScreen.kt · (각성은 SwordDetail에)

"공격하기" 버튼을 따로 누르게 하면 러닝 앱이 아니게 됩니다.

못 찾았다는 이유로. 첫 검은 자동 장착하도록 고쳤고(같은 러닝 데미지 663 → 2,381), API 테스트로

## 8. 위험

- **경계 데이터 신선도** — 행정동은 개편됩니다. 코드가 바뀌면 기존 보스 기록이 뜹니다.
  `regions`에 `valid_from`을 두고, 사라진 코드는 기록 보존용으로 남깁니다.
- **한국 밖** — 데이터셋이 한국 전용입니다. 해외 러닝은 보스가 없습니다. 지오해시 격자 폴백을
  나중에 얹을 수 있게 `regions.level`에 `'grid'`를 허용해 둡니다.
- **인구 희박 지역** — 시골 동은 영원히 1명입니다. HP 곡선이 이미 이걸 처리하지만, 참가자 1명
  기준이 "일주일에 4회 러닝"이라 부담스러울 수 있습니다. B7에서 조정.
- **위치 프라이버시** — 기여 순위표에 사람 이름이 뜹니다. 어느 동네에서 뛰는지가 노출됩니다.
  **집 주소 수준은 아니지만 동네 수준은 노출**되므로, 순위표 참여를 끌 수 있어야 합니다
  (`users.boss_anonymous`). 출시 전 필수 — `docs/RUNDEX_LESSONS.md` P2-2 개인정보 항목과 함께 처리.
- **PostGIS 조회 비용** — 러닝당 최대 300회 point-in-polygon. GIST 인덱스로 밀리초 단위지만,
  Edge Function 타임아웃을 감안해 경로를 60점으로 다운샘플해서 조회합니다(거리 배분 정확도에는
  영향이 미미).
